Set up Reverse Proxy for ntfy from scratch and send your first push notification through Cloudflare Workers.

## Prerequisites

Before you begin, make sure you have the following ready:

- **Node.js** — v22 or v24 (LTS recommended for stability)
- **npm** — v10 or later, which ships with supported Node.js versions
- **Cloudflare account** — A free or paid account with a registered domain (Workers and Email Routing are both available on the free plan)
- **ntfy <Terminology title="an ntfy instance defined by name, URL, and token" to="/docs/reference/terminology#server">server</Terminology>** — At least one self-hosted ntfy instance with token authentication enabled

:::info
Your ntfy <Terminology title="an ntfy instance defined by name, URL, and token" to="/docs/reference/terminology#server">server</Terminology> needs `base-url` set to its public URL and `behind-proxy` set to `true`. If you plan to receive binary attachments (images, files), also configure `attachment-cache-dir`. See the [ntfy self-hosting documentation](https://docs.ntfy.sh/config/) for details.
:::

## Install

Install the package globally to use the `nrp` command anywhere:

```bash
npm install -g ntfy-reverse-proxy
```

Or run it directly without installing:

```bash
npx ntfy-reverse-proxy
```

Both `ntfy-reverse-proxy` and `nrp` are registered as CLI aliases — they do the same thing.

## First-Time Setup

The interactive config menu guides you through everything you need for a working deployment.

1. Run `nrp` to launch the interactive config menu.
2. **Add at least one ntfy <Terminology title="an ntfy instance defined by name, URL, and token" to="/docs/reference/terminology#server">server</Terminology>.** Each <Terminology title="an ntfy instance defined by name, URL, and token" to="/docs/reference/terminology#server">server</Terminology> needs a name, a URL starting with `https://`, and a token starting with `tk_`.
3. **Add at least one <Terminology title="a notification source configuration" to="/docs/reference/terminology#context">context</Terminology>.** Choose a name, <Terminology title="module that transforms a payload into a notification" to="/docs/reference/terminology#interpreter">interpreter</Terminology>, <Terminology title="the ntfy channel a context publishes notifications to" to="/docs/reference/terminology#topic">topic</Terminology>, delivery mode, and assign one or more <Terminology title="an ntfy instance defined by name, URL, and token" to="/docs/reference/terminology#server">servers</Terminology>.
4. **Update settings.** Set the `worker_name` and `base_domain` to match your Cloudflare domain.
5. **Run `nrp validate`** from the CLI to check config integrity. Validation also runs automatically as part of the deploy step. This catches missing fields and invalid references before deployment.
6. **Run deploy** to generate `wrangler.toml` and deploy to Cloudflare Workers.

:::tip
The CLI validates config against its schema on every load. You can also run validation manually with `nrp validate` or through the interactive menu.
:::

## Sending Your First Notification

After deployment, each HTTP <Terminology title="a notification source configuration" to="/docs/reference/terminology#context">context</Terminology> gets a subdomain route in the format `{context-id}.{base_domain}`. Test it with a simple `curl` command.

### Plain Text Notification

```bash
curl -X POST https://{context-id}.ntfy.example.com \
  -H "Content-Type: text/plain" \
  -d "Hello from ntfy-reverse-proxy!"
```

### Authenticated Notification

If the <Terminology title="a notification source configuration" to="/docs/reference/terminology#context">context</Terminology> has a token configured, include the `Authorization` header:

```bash
curl -X POST https://{context-id}.ntfy.example.com \
  -H "Authorization: Bearer your-context-token" \
  -d "Authenticated notification"
```

### Landing Page

GET requests to any <Terminology title="a notification source configuration" to="/docs/reference/terminology#context">context</Terminology> URL return a <Terminology title="HTML status page returned on GET requests" to="/docs/reference/terminology#landing-page">landing page</Terminology> showing "Reverse Proxy for ntfy" with an operational status badge. When `show_response_output` is enabled, the page also includes a collapsible section with the full configuration, with sensitive values masked.

## If Something Goes Wrong

If deployment fails or notifications are not arriving, check [Troubleshooting](/docs/reference/troubleshooting/). Common first-time issues include:

- Cloudflare's bot protection blocking webhooks (403 errors)
- DNS propagation delays after deployment
- ntfy <Terminology title="an ntfy instance defined by name, URL, and token" to="/docs/reference/terminology#server">server</Terminology> misconfiguration
