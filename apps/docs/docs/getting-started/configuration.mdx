`config.json` defines the <Terminology title="an ntfy instance defined by name, URL, and token" to="/docs/reference/terminology#server">servers</Terminology>, <Terminology title="a notification source configuration" to="/docs/reference/terminology#context">contexts</Terminology>, and global settings that the Cloudflare <Terminology title="Cloudflare-hosted entry point that runs the pipeline" to="/docs/reference/terminology#worker">Worker</Terminology> reads at runtime.

## Overview

The configuration lives in a single `config.json` file managed through the CLI (never edited by hand in production). The file is gitignored — only `config.sample.json` is committed.

The config has three top-level sections: `settings`, `servers`, and `contexts`.

## Settings

| Field                  | Type      | Description                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| :--------------------- | :-------- | :---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `worker_name`          | `string`  | Name of the Cloudflare <Terminology title="Cloudflare-hosted entry point that runs the pipeline" to="/docs/reference/terminology#worker">Worker</Terminology>. Used in <Terminology title="Cloudflare Workers config file generated from config.json" to="/docs/reference/terminology#wranglertoml">wrangler.toml</Terminology> generation.                                                                                                                                                                                                                                                                                                                       |
| `base_domain`          | `string`  | The <Terminology title="single domain all context subdomains register under" to="/docs/reference/terminology#base-domain">domain</Terminology> under which all <Terminology title="a notification source configuration" to="/docs/reference/terminology#context">context</Terminology> subdomains are registered (e.g., `ntfy.example.com`).                                                                                                                                                                                                                                                                                                                      |
| `show_response_output` | `boolean` | When `true`, POST/PUT responses include detailed <Terminology title="the show_response_output setting" to="/docs/reference/terminology#debug-mode">debug output</Terminology> (<Terminology title="a notification source configuration" to="/docs/reference/terminology#context">context</Terminology>, <Terminology title="module that transforms a payload into a notification" to="/docs/reference/terminology#interpreter">interpreter</Terminology>, <Terminology title="an ntfy instance defined by name, URL, and token" to="/docs/reference/terminology#server">server</Terminology> results). Set to `false` in production to avoid leaking information. |

:::warning
Keep `show_response_output` set to `false` in production. Enabling it exposes <Terminology title="a notification source configuration" to="/docs/reference/terminology#context">context</Terminology> names, <Terminology title="module that transforms a payload into a notification" to="/docs/reference/terminology#interpreter">interpreter</Terminology> types, and per-<Terminology title="an ntfy instance defined by name, URL, and token" to="/docs/reference/terminology#server">server</Terminology> delivery results in HTTP responses.
:::

## Servers

Each <Terminology title="an ntfy instance defined by name, URL, and token" to="/docs/reference/terminology#server">server</Terminology> represents an ntfy instance. <Terminology title="an ntfy instance defined by name, URL, and token" to="/docs/reference/terminology#server">Servers</Terminology> are defined once and referenced by name from <Terminology title="a notification source configuration" to="/docs/reference/terminology#context">contexts</Terminology>.

| Field    | Type     | Description                                                                                                                                                                                                                                                                                                                                     |
| :------- | :------- | :---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `name`   | `string` | Unique identifier for this <Terminology title="an ntfy instance defined by name, URL, and token" to="/docs/reference/terminology#server">server</Terminology>. Referenced by <Terminology title="a notification source configuration" to="/docs/reference/terminology#context">contexts</Terminology> in `primary_server` and `servers` fields. |
| `server` | `string` | Full URL of the ntfy <Terminology title="an ntfy instance defined by name, URL, and token" to="/docs/reference/terminology#server">server</Terminology> (must start with `https://`).                                                                                                                                                           |
| `token`  | `string` | Access token for the ntfy <Terminology title="an ntfy instance defined by name, URL, and token" to="/docs/reference/terminology#server">server</Terminology> (must start with `tk_`). Created via the ntfy CLI.                                                                                                                                 |

```json
{
  "name": "primary",
  "server": "https://ntfy.example.com",
  "token": "tk_your_token_here"
}
```

## Contexts

<Terminology title="a notification source configuration" to="/docs/reference/terminology#context">Contexts</Terminology> define notification sources. Each webhook source or email sender maps to one <Terminology title="a notification source configuration" to="/docs/reference/terminology#context">context</Terminology>. There are two types: HTTP <Terminology title="a notification source configuration" to="/docs/reference/terminology#context">contexts</Terminology> and email <Terminology title="a notification source configuration" to="/docs/reference/terminology#context">contexts</Terminology>.

### HTTP Context

| Field               | Type       | Required | Description                                                                                                                                                                                                                                                                                                                                                               |
| :------------------ | :--------- | :------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `id`                | `string`   | Yes      | Unique identifier. Becomes the subdomain in the route (e.g., `{id}.ntfy.example.com`). Auto-generated by the CLI.                                                                                                                                                                                                                                                         |
| `name`              | `string`   | Yes      | Human-readable name for display in CLI and responses.                                                                                                                                                                                                                                                                                                                     |
| `type`              | `"http"`   | Yes      | Must be `"http"` for webhook <Terminology title="a notification source configuration" to="/docs/reference/terminology#context">contexts</Terminology>.                                                                                                                                                                                                                    |
| `interpreter`       | `string`   | Yes      | Which <Terminology title="module that transforms a payload into a notification" to="/docs/reference/terminology#interpreter">interpreter</Terminology> to use. One of: `plain-text`, `ntfy-json`, `statuspage`, `synology`, `seerr`, `pfsense`, `unifi`.                                                                                                                  |
| `topic`             | `string`   | Yes      | The ntfy <Terminology title="the ntfy channel a context publishes notifications to" to="/docs/reference/terminology#topic">topic</Terminology> to publish to.                                                                                                                                                                                                             |
| `error_topic`       | `string`   | No       | Optional ntfy <Terminology title="optional topic that receives failure notifications" to="/docs/reference/terminology#error-topic">topic</Terminology> where authentication and interpretation errors are sent as JSON debug <Terminology title="a binary file delivered alongside a notification" to="/docs/reference/terminology#attachment">attachments</Terminology>. |
| `error_events`      | `string[]` | No       | Which error categories notify `error_topic`. Any of `authentication`, `interpretation`. Omit to notify on both (the default); set to `["interpretation"]` to keep <Terminology title="module that transforms a payload into a notification" to="/docs/reference/terminology#interpreter">interpreter</Terminology>-error alerts while silencing authentication-failure noise. No effect unless `error_topic` is set.                                                                                           |
| `mode`              | `string`   | Yes      | Delivery mode: `"send-once"` or `"send-all"`.                                                                                                                                                                                                                                                                                                                             |
| `show_visitor_info` | `boolean`  | Yes      | When `true`, appends visitor IP, location, and ISP details to the notification body.                                                                                                                                                                                                                                                                                      |
| `primary_server`    | `string`   | Yes      | Name of the preferred <Terminology title="an ntfy instance defined by name, URL, and token" to="/docs/reference/terminology#server">server</Terminology> (must match a <Terminology title="an ntfy instance defined by name, URL, and token" to="/docs/reference/terminology#server">server</Terminology>'s `name`). Tried first in `send-once` mode.                     |
| `servers`           | `string[]` | Yes      | Ordered list of <Terminology title="an ntfy instance defined by name, URL, and token" to="/docs/reference/terminology#server">server</Terminology> names. At least one required.                                                                                                                                                                                          |
| `token`             | `string`   | No       | Optional authentication token for this <Terminology title="a notification source configuration" to="/docs/reference/terminology#context">context</Terminology>. When set, incoming requests must include `Authorization: Bearer {token}`.                                                                                                                                 |

### Email Context

| Field               | Type       | Required | Description                                                                                                                                                                                                                 |
| :------------------ | :--------- | :------- | :-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `id`                | `string`   | Yes      | Unique identifier. Must match the local part of the email address (e.g., `pfsense` for `pfsense@ntfy.example.com`). Allows letters, digits, dots, underscores, and dashes.                                                  |
| `name`              | `string`   | Yes      | Human-readable name.                                                                                                                                                                                                        |
| `type`              | `"email"`  | Yes      | Must be `"email"` for email <Terminology title="a notification source configuration" to="/docs/reference/terminology#context">contexts</Terminology>.                                                                       |
| `interpreter`       | `string`   | Yes      | Which <Terminology title="module that transforms a payload into a notification" to="/docs/reference/terminology#interpreter">interpreter</Terminology> to use.                                                              |
| `topic`             | `string`   | Yes      | The ntfy <Terminology title="the ntfy channel a context publishes notifications to" to="/docs/reference/terminology#topic">topic</Terminology> to publish to.                                                               |
| `error_topic`       | `string`   | No       | Optional <Terminology title="optional topic that receives failure notifications" to="/docs/reference/terminology#error-topic">error topic</Terminology>.                                                                    |
| `error_events`      | `string[]` | No       | Which error categories notify `error_topic`. Any of `authentication`, `interpretation`. Omit for both (the default); e.g. `["interpretation"]` to mute authentication-failure noise. No effect unless `error_topic` is set. |
| `mode`              | `string`   | Yes      | Delivery mode: `"send-once"` or `"send-all"`.                                                                                                                                                                               |
| `show_visitor_info` | `boolean`  | Yes      | For email <Terminology title="a notification source configuration" to="/docs/reference/terminology#context">contexts</Terminology>, this setting has no effect — visitor details are only available for HTTP requests.      |
| `primary_server`    | `string`   | Yes      | Preferred <Terminology title="an ntfy instance defined by name, URL, and token" to="/docs/reference/terminology#server">server</Terminology> name.                                                                          |
| `servers`           | `string[]` | Yes      | Ordered <Terminology title="an ntfy instance defined by name, URL, and token" to="/docs/reference/terminology#server">server</Terminology> name list.                                                                       |
| `allowed_from`      | `string`   | No       | Sender filter. Supports exact match (`user@example.com`) or wildcard (`*@example.com`). Case-insensitive.                                                                                                                   |

## Full Example

This example shows a complete `config.json` with two <Terminology title="an ntfy instance defined by name, URL, and token" to="/docs/reference/terminology#server">servers</Terminology> and a mix of HTTP and email <Terminology title="a notification source configuration" to="/docs/reference/terminology#context">contexts</Terminology>.

```json
      "name": "primary",

      "token": "tk_replace_with_your_token"

    {

    }
  ],

    {
      "id": "replace_with_random_string",
      "name": "GitHub Status",
      "type": "http",
      "interpreter": "statuspage",
      "topic": "github-status",
      "error_topic": "errors",
      "error_events": ["interpretation"],
      "mode": "send-once",
      "show_visitor_info": false,
      "primary_server": "primary",
      "servers": ["primary", "fallback"]
    },
    {
      "id": "replace_with_random_string",
      "name": "Seerr Requests",
      "type": "http",
      "interpreter": "seerr",
      "topic": "media-requests",
      "mode": "send-once",
      "show_visitor_info": false,
      "primary_server": "primary",
      "servers": ["primary"],
      "token": "replace_with_auth_token"
    },
    {
      "id": "replace_with_random_string",
      "name": "Synology NAS",
      "type": "http",
      "interpreter": "synology",
      "topic": "nas-alerts",
      "mode": "send-once",
      "show_visitor_info": true,
      "primary_server": "primary",
      "servers": ["primary"],
      "token": "replace_with_auth_token"

    {
      "id": "replace_with_random_string",
      "name": "Generic Webhook",

    }
  ]
}
```

## Validation

The CLI validates config against its schema on every load. Validation checks include:

- **Structural** — All required fields are present and correctly typed.
- **<Terminology title="an ntfy instance defined by name, URL, and token" to="/docs/reference/terminology#server">Server</Terminology> references** — Every `primary_server` and every entry in `servers` must match an existing <Terminology title="an ntfy instance defined by name, URL, and token" to="/docs/reference/terminology#server">server</Terminology> `name`.
- **Duplicate <Terminology title="a notification source configuration" to="/docs/reference/terminology#context">context</Terminology> IDs** — No two <Terminology title="a notification source configuration" to="/docs/reference/terminology#context">contexts</Terminology> can share the same `id`.
- **Token format** — <Terminology title="an ntfy instance defined by name, URL, and token" to="/docs/reference/terminology#server">Server</Terminology> tokens must start with `tk_`.
- **URL format** — <Terminology title="an ntfy instance defined by name, URL, and token" to="/docs/reference/terminology#server">Server</Terminology> URLs must start with `https://`.

:::tip
Run validation manually with `nrp validate` or through the interactive menu to catch issues before deployment.
:::
