Pass the input through as the notification body with no transformation — the simplest <Terminology title="Turns one app's raw alert into a clean ntfy message" to="/docs/reference/terminology#how-it-works">interpreter</Terminology> available.

## Behavior

- **String input** — Used directly as the body.
- **Binary input** — Preserved byte-for-byte and uploaded to ntfy as an attachment-only notification instead of being decoded as UTF-8 text.
- **Object input** — Serialized as pretty-printed JSON (2-space indent).

No title, priority, tags, or other notification fields are set by this <Terminology title="Turns one app's raw alert into a clean ntfy message" to="/docs/reference/terminology#how-it-works">interpreter</Terminology>. The notification title falls back to the <Terminology title="One alert source: its address, interpreter, and topic" to="/docs/reference/terminology#how-it-works">context</Terminology>'s `name` field.

:::info
<Terminology title="The X-Title, X-Priority, and friends sent to ntfy" to="/docs/reference/terminology#ntfy-servers-and-messages">ntfy headers</Terminology> like `X-Title` or `X-Priority` on the incoming HTTP request are **not** forwarded to the ntfy <Terminology title="One of your ntfy instances: a name, URL, and token" to="/docs/reference/terminology#ntfy-servers-and-messages">server</Terminology>. The proxy builds outgoing headers from the <Terminology title="Turns one app's raw alert into a clean ntfy message" to="/docs/reference/terminology#how-it-works">interpreter</Terminology>'s <Terminology title="The title, body, and tags an interpreter hands back" to="/docs/reference/terminology#how-it-works">notification object</Terminology>, not from the incoming request. If you need control over title, priority, tags, and other ntfy fields, use the [`ntfy-json`](/docs/interpreters/ntfy-json/) <Terminology title="Turns one app's raw alert into a clean ntfy message" to="/docs/reference/terminology#how-it-works">interpreter</Terminology> instead.
:::

## Use Cases

- Testing your deployment with a simple curl command.
- Generic webhook sources that send unstructured payloads.
- Services where you do not need rich formatting and the raw body is sufficient.

## Example

```bash
curl -X POST https://{context-id}.ntfy.example.com \
  -d "Deployment to production finished successfully."
```

To add a title and priority, use the `ntfy-json` <Terminology title="Turns one app's raw alert into a clean ntfy message" to="/docs/reference/terminology#how-it-works">interpreter</Terminology> with a JSON payload instead:

```bash
curl -X POST https://{context-id}.ntfy.example.com \
  -H "Content-Type: application/json" \
  -d '{"title": "Build Complete", "body": "Deployment to production finished.", "priority": 3}'
```
